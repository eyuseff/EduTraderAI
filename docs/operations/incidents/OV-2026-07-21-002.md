## Analysis and disposition

- Reproduction: Render Paper Order with LOW at 9/8/11. The error and minimum-price
  explanation appear while the static metric reads `Approved quantity: 250`.
- Root cause: **Implementation/presentation** — the label does not distinguish a
  calculated size from an approved size when the plan is rejected. Deterministic
  policy and broker-submission behavior are correct.
- Trading outcome affected? No.
- Instrumentation outcome affected? No additional effect beyond the Session 1
  export loss recorded in `OV-2026-07-21-001`.
- Corrective action: Added a presentation-only mapping that renders an em dash
  for `Approved quantity` when a decision is rejected and returns the existing
  integer quantity unchanged when it is approved. The Streamlit metric now uses
  that mapping. No decision, policy, sizing, execution, scanner, broker, or
  operational-metric code was changed.
- Regression evidence: `tests/test_paper_order_preview_wiring.py` verifies that
  a rejected decision retaining a calculated quantity of 250 cannot render 250,
  an approved quantity of 100 remains 100, and the actual `app.py` metric is
  wired through the rejection-aware presentation mapping. All 25 affected UI and
  preview tests passed.
- Rendered UI evidence: Streamlit AppTest displayed `Approved quantity: 100` for
  an approved 100/97.5/105 proposal and `Approved quantity: —` for rejected LOW
  at 9/8/11, with the rejection error visible and no submission action.
- Release verification: `make verify` passed 390 tests with 84.3% line, 62.8%
  branch, and 80.0% combined coverage. All 17 architecture tests passed.
- Performance evidence: Post-fix medians remained within +0.0% to +1.6% of the
  RC baseline across planner, preview, submit, supervisor, and scanner paths.
- Resolved by/date: **Closed 2026-07-21** by the authorized presentation-only
  corrective action.
