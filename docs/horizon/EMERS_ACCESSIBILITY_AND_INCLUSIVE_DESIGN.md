# EMERS Accessibility and Inclusive Design

## 1. Purpose

Define accessibility direction without claiming formal compliance.

## 2. Accessibility principles

Financial decision support should be readable, navigable, understandable, color-independent, and recoverable.

## 3. Visual accessibility

Use clear hierarchy, sufficient contrast, readable type, and non-color state indicators.

## 4. Keyboard operation

Material flows should be operable by keyboard before compliance claims.

## 5. Screen-reader structure

Status, errors, tables, forms, and confirmations need semantic structure.

## 6. Focus management

Focus should move predictably, especially after errors and confirmations.

## 7. Color independence

Color must not be the only indicator of profit/loss, risk, broker status, or warnings.

## 8. Text scaling

Layouts should tolerate practical text scaling without hiding risk or action state.

## 9. Numerical readability

Numbers require alignment, units, signs, precision, and labels.

## 10. Motion sensitivity

Motion should be minimal and disableable where needed.

## 11. Cognitive accessibility

Use plain language, progressive disclosure, and clear next steps.

## 12. Plain language

Explain broker state, risk, and uncertainty without unnecessary jargon.

## 13. Error recovery

Errors should say what happened, impact, and safest next action.

## 14. Mobile accessibility

Mobile must preserve touch target size, readable numbers, and assistive support.

## 15. Financial-data accessibility

Tables and charts need textual summaries, units, and accessible labels.

## 16. Testing requirements

Future implementations should include keyboard, screen-reader, contrast, text scaling, motion, and mobile accessibility testing.

## 17. Documentation

Document accessibility decisions, limitations, and test evidence.

## 18. Limitations

No formal accessibility compliance claim is made by Horizon.

## 19. Future conformance assessment

Future implementations should be designed toward an appropriate recognized accessibility standard and independently tested before making compliance claims.

## 20. Open decisions

Open decisions include target standard, testing tools, reviewer process, and supported devices.
