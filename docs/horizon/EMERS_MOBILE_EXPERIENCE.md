# EMERS Mobile Experience

## 1. Purpose

Define mobile's future role without authorizing mobile implementation.

## 2. Mobile role

Mobile is initially for monitoring, alerts, review, acknowledgement, and controlled approval only after separate security and product validation.

## 3. Mobile principles

Mobile must not become a simplified interface that hides important risk.

## 4. Core mobile capabilities

Possible capabilities include home summary, portfolio review, alerts, broker status, position monitoring, emergency controls, and later carefully validated approval.

## 5. Home summary

Show system mode, risk condition, unresolved broker events, critical alerts, and required action.

## 6. Portfolio review

Show exposure, positions, risk budget, and attention items.

## 7. Alerts

Alerts must be sparse, actionable, and severity-accurate.

## 8. Approval possibilities

Mobile approval is not authorized by this document. If later approved, it requires strong confirmation, identity, session, risk visibility, and broker-state clarity.

## 9. Broker status

Broker state must remain explicit and never collapse submitted into completed.

## 10. Position monitoring

Position monitoring should preserve risk and data freshness.

## 11. Emergency controls

Emergency stop may be a priority future mobile control, subject to security validation.

## 12. Authentication

Mobile requires strong authentication before material use.

## 13. Session security

Sessions need timeout, revocation, and protection against unattended approval.

## 14. Device security

Device loss, push privacy, and local storage must be considered.

## 15. Responsive versus native

Responsive web and native apps remain options; no decision is made.

## 16. Offline and poor connectivity

Offline states must not allow broker assumptions or unsafe approvals.

## 17. Accessibility

Mobile must preserve readable financial data and assistive-technology support.

## 18. Prohibited mobile patterns

No hidden risk, swipe-to-trade, simplified broker state, urgency nudges, or approval without full consequence visibility.

## 19. Delivery dependencies

Dependencies include identity, authorization, notification security, API design, and broker-state reconciliation.

## 20. Open decisions

Open decisions include responsive/native strategy, approval policy, push channels, and biometric use.
