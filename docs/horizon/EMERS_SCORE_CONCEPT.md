# EMERS Score Concept

## 1. Purpose

Define the EMERS Score as a future concept, not an implementation authorization.

## 2. Concept statement

The EMERS Score is a possible future measure of decision-process discipline, not predicted profitability.

## 3. Why the score exists

It may help users improve process quality, risk discipline, documentation, and follow-through.

## 4. What it should not measure

It should not measure guaranteed return potential, trading frequency, excitement, or short-term profit without risk context.

## 5. Candidate dimensions

Risk-policy adherence, position-sizing discipline, diversification, concentration control, plan completeness, approval discipline, plan adherence, documentation quality, unresolved-action management, post-trade review completion, repeated rule violations, data-quality awareness, and emotional or impulsive behavior only where valid, consented, and supportable evidence exists.

## 6. Potential inputs

Trade plans, risk assessments, approvals, evidence records, broker reconciliation, post-trade reviews, and data-quality warnings.

## 7. Weighting principles

Weights should be explainable, evidence-backed, and not reward trading frequency.

## 8. Explainability

Users must see why a score changed.

## 9. User control

Users should be able to disable or ignore score presentation if it creates pressure.

## 10. Data requirements

Inputs must be reliable, consented where personal behavior is inferred, and auditable.

## 11. Missing-data behavior

Missing data must not be treated as misconduct.

## 12. Score stability

Scores should avoid noisy swings that drive emotional behavior.

## 13. Historical comparison

Historical comparison should focus on process improvement, not shame.

## 14. Risk of misuse

Risks include pressure, false precision, gamification, overconfidence, and commercial misuse.

## 15. Behavioral risks

The score must not shame users for losses, reward trading frequency, create pressure to act, replace portfolio-risk measures, hide calculation, treat missing data as misconduct, or become a marketing gimmick.

## 16. Validation

Validation requires behavioral-risk review, user research, calculation review, and misuse testing.

## 17. Governance

Any score requires governance, versioning, and clear documentation.

## 18. Implementation prerequisites

Prerequisites include stable data model, evidence quality, user research, accessibility review, and opt-out/disable policy.

## 19. Current status

The EMERS Score is conceptual and not authorized for implementation.

## 20. Open decisions

Open decisions include dimensions, weights, display, opt-out, validation method, and release gate.
