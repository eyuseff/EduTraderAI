# EduTraderAI 4.0.0-rc1

- Release date: 2026-07-20
- Status: Release candidate
- Trading mode: Paper-only, long-only

## Release summary

EduTraderAI v4.0 unifies manual Paper Orders and scanner automation around the
same deterministic planning, policy, execution, safety, and explainability
boundaries. Manual preview/submission and supervised scanner preview/submission
now share `TradePlanner`. Concrete broker snapshots and order translation remain
outside Volcanoes through narrow adapters.

The release candidate adds no trading policies, sizing changes, scanner
strategies, live-trading capability, durable event storage, or AI execution
logic.

It also adds an operational-validation layer: explicitly injected process-local
metrics, a development-only dashboard, operator-triggered sanitized JSON export,
an RC runbook and acceptance plan, and a GitHub Actions gate that runs the same
`make verify` command used locally.

## Supported workflows

- Manual deterministic preview with immutable broker snapshot inputs.
- Manual deterministic paper submission with fresh-snapshot drift rejection.
- Supervised scanner preview-only runs.
- Supervised scanner paper submissions with idempotency, cooldown policy, and
  same-symbol serialization.
- Full legacy manual preview/submission rollback.
- Full legacy scanner preview/submission rollback.

The complete dependency inventory and canonical diagram are in
[`docs/architecture/README.md`](../architecture/README.md).

## Active feature flags

```python
USE_DETERMINISTIC_PREVIEW = True
USE_DETERMINISTIC_SUBMISSION = True
USE_DETERMINISTIC_SCANNER = True
```

Manual flags must change together. Mixed deterministic/legacy manual generations
fail startup validation before broker construction.

### Rollback procedure

1. For manual rollback, set both `USE_DETERMINISTIC_PREVIEW` and
   `USE_DETERMINISTIC_SUBMISSION` to `False` and restart Streamlit.
2. For scanner rollback, set `USE_DETERMINISTIC_SCANNER` to `False` and restart
   Streamlit.
3. Confirm the development platform-health report lists the intended legacy
   path before accepting paper orders.

Removal conditions for every flag are recorded in the architecture inventory.

## Startup validation

Before broker composition or execution, the app validates:

- all deterministic flags are real booleans;
- manual preview/submission generations match;
- scanner mode matches its rollback flag;
- every policy value is finite and within its supported range;
- maximum single-position exposure does not exceed total exposure;
- the selected broker mode is supported and paper-only;
- Alpaca credentials are present only when Alpaca Paper is selected; and
- the v4 adapter's long-only requirement remains enabled.

Invalid configuration produces a clear Streamlit error and stops execution.
The simulator requires no Alpaca credentials. Valid credentials are never added
to the diagnostic payload.

## Platform health diagnostics

`PlatformHealthReport` is immutable and presentation-neutral. It reports active
and rollback paths, broker mode, deterministic flags, publisher type,
persistence mode, supervisor state mode, scanner execution mode, and known
limitations. It imports neither Streamlit nor concrete brokers. Development mode
displays it on the Safety Dashboard.

## Test and coverage baseline

- Full pytest suite: **387 passed** at baseline capture.
- Requested coverage scope: all `volcanoes/`, all `adapters/`, and only
  `engine/supervised_brain.py` from the root engine generation.
- Line coverage: **84.2%** (2,817 / 3,344 statements).
- Branch coverage: **62.7%** (524 / 836 branches).
- Combined branch-aware coverage: **79.9%**.
- Enforced minimum: **79.0% combined**.

The 79.0% floor is deliberately just below the measured 79.9% baseline. It
prevents coverage regression without pretending older, inactive Volcanoes
generations are fully exercised. No production files are excluded. The only
omitted engine files are `engine/brain.py`, `engine/cycle_report.py`, and
`engine/__init__.py`, because the requested engine scope is specifically
`engine/supervised_brain.py`. Coverage.py's normal exclusions for protocol and
abstract bodies remain unchanged.

### Uncovered critical paths

- Defensive constructor/type-error branches in supervisor and scanner
  composition.
- Rare `SubmitTradeService` cancellation, immediate-fill, and concurrent
  duplicate-reservation branches.
- Supervisor catch-all abortion and invalid-clock branches.
- Impossible-state guards in `SupervisedEduTraderBrain` for an approved result
  missing its preview or submission payload.
- Older inactive Volcanoes database, scanner, guardian, forge, and market
  generations, which lower the repository-wide baseline but are not active v4
  execution paths.

Broker rejection, broker exception, plan drift, policy rejection, duplicate
scanner signals, and human/scanner collision are covered by acceptance tests.

## Runtime performance baseline

Measurements use Python 3.14.6 on macOS 26.5.2 arm64, 300 recorded iterations
after 30 warmups, a $100,000 immutable account fixture, AAPL at
100/97.5/105, and an in-memory zero-delay paper broker. Values are baselines,
not optimization targets.

|---|---:|---:|---:|
| `TradePlanner.plan` | 10.709 µs | 10.958 µs | 13.125 µs |
| `PreviewTradeService.preview` | 16.625 µs | 19.041 µs | 27.959 µs |
| `SubmitTradeService.submit`, excluding broker delay | 22.791 µs | 26.583 µs | 32.291 µs |
| `ExecutionSupervisor.execute` | 58.105 µs | 70.250 µs | 119.667 µs |
| Scanner signal-to-decision | 72.166 µs | 85.708 µs | 142.208 µs |

Reproduce with:

```bash

```

## Release verification

Install development dependencies and run the unified non-zero-on-failure gate:

```bash
python3 -m pip install -r requirements-dev.txt
make verify
```

The gate runs Black, Ruff, MyPy over the supported deterministic boundary,
architecture tests, import/bytecode smoke tests, the full pytest suite, branch
coverage, the 79.0% threshold, and a JSON coverage artifact in ignored
`build/coverage.json`.

## Known limitations and deferred infrastructure

- `NullEventPublisher` provides no event durability, retention, or replay.
- Supervisor state, idempotency, cooldowns, and symbol locks reset with the
  process and are not shared between instances.
- Broker snapshots do not expose transactional versions.
- The supervisor market-state policy has no authoritative adapter.
- Alpaca Paper remains an external network dependency and is not used by release
  acceptance tests.
- External schedulers have no durable shared supervisor runtime.
- Operational metrics reset with the process and use aggregate, fixed-cardinality
  observations only.
- Validation JSON is a manual local export under ignored `build/`; it is not an
  event store or broker-reconciliation record.
- Execution remains long-only and paper-only.

The stable-release acceptance criteria and observation ledger are maintained in
[`docs/operations/VALIDATION_PLAN.md`](../operations/VALIDATION_PLAN.md) and
[`docs/operations/VALIDATION_LOG.md`](../operations/VALIDATION_LOG.md).

Durable events, distributed locks, new policies, scanner strategies, live
trading, portfolio optimization, and AI execution logic remain intentionally
deferred.
