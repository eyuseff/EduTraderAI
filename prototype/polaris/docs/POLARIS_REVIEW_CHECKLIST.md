# Polaris Phase 1 Review Checklist

- [ ] Can a reviewer understand the dashboard condition in five seconds?
- [ ] Is risk visible before expected reward?
- [ ] Is Paper mode visible throughout the workflow?
- [ ] Is approval language explicit and exactly `AUTHORIZE PAPER ORDER`?
- [ ] Are all risk acknowledgements required before approval?
- [ ] Does the workflow distinguish application intent, outbound request, broker acknowledgment, broker execution, and reconciled final state?
- [ ] Does unresolved state avoid the word completed?
- [ ] Does cancellation require separate broker confirmation?
- [ ] Are uncertainty and stale/degraded data visible?
- [ ] Does degraded mode block consequential actions?
- [ ] Does emergency stop block new authorization?
- [ ] Are evidence events generated for material prototype actions?
- [ ] Is the experience calm and free of pressure-to-trade patterns?
- [ ] Is performance shown with risk context instead of as a standalone celebration?
- [ ] Are controls keyboard accessible with visible focus?
- [ ] Are status meanings supported by text, not color alone?
- [ ] Are no real credentials, broker connections, or external requests present?
- [ ] Does the layout remain understandable at narrower widths?
